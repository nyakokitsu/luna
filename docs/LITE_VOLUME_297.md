# Нативная громкость Лайта на прошивке .297

Проверенная конфигурация (16 ноября 2026):

- модель Luna `yandexmicro`, device tree — `yandex,station-micro` и
  `amlogic, axg`;
- полный номер прошивки `0.369.1.46.4778262442.20261013.297`;
- исходники Luna 0.2.28 с этим исправлением;
- официальный AirPlay `ryysel/Station-airplay` 2.1.11, без изменений его кода.

## Причина

`verified_build` для этой сборки требовал элемент device tree
`yandex,yandexmicro` — строку model ID. Реальная плата объявляет
`yandex,station-micro` (тот же токен уже используется в `install.sh` для
определения платы). Квалификация не проходила, поэтому Luna не выбирала
нативный backend и писала ALSA `Master` напрямую; `GET /api/volume` читал то же
зеркало.

Исправление — только точное совпадение элемента `yandex,station-micro` для этой
сборки. Похожие имена (`prefix-yandex,station-micro`,
`yandex,station-micro-suffix`) и model ID квалификацию не проходят. Протокол не
менялся: чтение состояния `stereo_pair`, `VolumeSet` через `iohub_clients`,
подтверждение фактического уровня и `Source=Button` для штатной индикации.

## Фактическая проверка протокола

На колонке вручную отправлен один `VolumeSet` через штатный IPC:

| Действие | Логическое состояние Quasar | ALSA `Master` |
|---|---|---|
| Исходно | 20% | 33% |
| `VolumeSet 60` | ACK 60% | 60% |

То есть maind принимает внешний уровень и зеркалит его в ALSA; нативный путь
для этой сборки работоспособен. Чтение `GET /api/volume` после исправления
должно возвращать логический уровень, а не зеркало.

## Важное ограничение AirPlay

На этой прошивке слышимую громкость AirPlay нативный путь не меняет. При
играющей AirPlay-музыке проверено:

- кнопки громкости на корпусе и команды «Алиса, громче» / «Алиса, громкость
  пять» громкость потока не меняют;
- `Master` (`numid=178`, 0–255) меняет значение, но не звук: прямой
  `aplay -D plug:dmix_spk` одного файла при 100% и 5% звучал одинаково;
- штатная музыка Алисы на слух меняется и двигает `Master`, а программный
  `softvol`-контрол не появляется: maind ослабляет свой тракт внутри себя, а
  AirPlay идёт отдельным процессом в `dmix`.

Поэтому этот PR исправляет логическое состояние и API громкости станции, но не
делает ползунок AirPlay слышимым на прошивке .297. Слышимую громкость AirPlay
обеспечивает приёмник (софтверное ослабление shairport); в Station-airplay для
`yandexmicro` выпускается `native_volume: false`. Обе правки независимы.

## Тесты

Добавлен тест точной пары build/DT, отказа model ID и похожих имён, а также
проверка, что прежние квалификации не изменились.

Рабочее окружение не позволяет собрать весь workspace под Linux, поэтому
`cargo test --workspace --locked` локально не запускался; его выполнит CI.
Изменённая функция `verified_build` не зависит от внешних крейтов: она вынута
из файла в отдельный модуль и собрана с rustc 1.100.0 вместе с теми же
проверками — компиляция прошла, все утверждения выполнены. Набор тестов
воспроизводит байты `/proc/device-tree/compatible` с колонки
(`yandex,station-micro\0amlogic, axg\0`) и номер сборки
`0.369.1.46.4778262442.20261013.297`.

## Не проверено

Другие прошивки и модели этим патчем не квалифицируются. Длительный прогон,
мультирум и голосовые пауза/продолжение/стоп не проверялись; патч меняет только
квалификацию нативной громкости.
