# Медиапровайдеры

Медиапровайдер — это пакетный адаптер для своего проигрывателя. Он сообщает
Luna, какие команды умеет выполнять, получает команды через runtime API и сам
отвечает за плеер, очередь, авторизацию и подтверждение результата.

Это не перехват штатного плеера Алисы и не готовая интеграция со Spotify.
Если нужно управлять штатным проигрывателем или голосовыми командами, это
отдельная интеграция.

## Описание адаптера

В `plugin.toml`:

```toml
permissions = ["exec", "media.provider"]

[media_provider]
label = "Интернет-радио"
actions = ["pause", "resume", "next", "previous"]
```

Команда `pause` обязательна. `resume`, `next` и `previous` добавляются по
необходимости. `label` — подпись провайдера длиной от 1 до 80 UTF-8 байт без
управляющих символов.

Старые пакеты без секции `[media_provider]` продолжают работать как раньше.
В текущем варианте это API для binary-плагинов; Lua-обёртка над ним не
добавляется автоматически.

## Runtime API

Luna передаёт процессу две переменные:

- `LUNA_API_URL` — адрес runtime API;
- `LUNA_API_TOKEN` — токен текущего запуска.

Токен передаётся в заголовке `X-Luna-Token`. Один пакет не может использовать
токен другого пакета.

| Запрос | Тело и результат |
| --- | --- |
| `POST /provider/state` | `{"state":"paused"}`, ответ `204` |
| `POST /provider/next` | пустое тело, ответ `null` или команда |
| `POST /provider/result` | `{"id":"…","success":true,"state":"paused"}`, ответ `204` |

Допустимые состояния: `unknown`, `paused`, `playing`.

Провайдер должен сообщать фактически наблюдаемое состояние не реже одного раза
в секунду. Если пять секунд нет обновления, он считается недоступным. Нельзя
отправлять `paused` только потому, что плееру была послана команда паузы.

`/provider/next` нужно опрашивать регулярно, например раз в 100–250 мс. Ответ
выглядит так:

```json
{"id":"uuid","action":"pause","expires_in_ms":4900}
```

Команду нужно выполнить один раз до истечения `expires_in_ms`, затем отправить
её ID и фактически полученное состояние. Успешная `pause` должна закончиться
состоянием `paused`, а `resume` — `playing`. Для `next` и `previous` адаптер
сам подтверждает смену трека или перезапускает плеер: Luna не угадывает её по
состоянию воспроизведения.

Команда доставляется только один раз. Потерянный ответ или отсутствие
результата через пять секунд превращает результат в `unknown`; Luna не повторяет
команду автоматически. Старые токены, повторные ID и запоздалые результаты
отклоняются.

## Выбор и управление

Основные endpoints Luna:

- `GET /api/media` — список провайдеров, их возможности, состояние, выбранный
  провайдер и последняя операция;
- `POST /api/media/select` с `{"provider":"namespace.package"}` — выбрать
  провайдера;
- `POST /api/media/command` с `{"action":"resume"}` — отправить команду
  выбранному провайдеру.

Изменения возвращают `202` и ID операции. Это означает «операция принята», а
не «операция уже выполнена». Результат нужно смотреть через `GET /api/media`.
Одновременно может выполняться только одна операция.

Перед переключением Luna требует, чтобы целевой провайдер был доступен и
поставлен на паузу. Если текущий провайдер играет, Luna сначала просит его
остановиться и меняет выбор только после подтверждения. При таймауте или
ошибке текущий выбор сохраняется.

После остановки выбранного пакета он остаётся выбранным, но недоступным.
Luna не запускает другой проигрыватель автоматически и не сохраняет выбор
между перезапусками.

## Необязательная индикация

Для короткой подписи можно использовать часы:

```text
GET  /api/clock
POST /api/clock/text
```

Текст часов имеет более строгие ограничения по символам, чем `label` провайдера.
Проверяйте `text_available` перед использованием. Подробности находятся в
[описании HTTP API](API.md).

## Проверка

```sh
cargo test --workspace --locked
cargo build --bin luna --locked
python3 tests/media_provider_http.py target/debug/luna
```

HTTP-тест запускает два тестовых binary-адаптера в loopback и проверяет
переключение, разные наборы команд и токены конкретного запуска. Он не
проверяет звук динамика, распознавание речи и особенности прошивки станции.
