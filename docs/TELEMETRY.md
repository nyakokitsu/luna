# Анонимная статистика

> Необязательный отчёт о станции на `stats.x-servers.ru`: что именно уходит,
> когда, как даётся и отзывается согласие.

Luna умеет отправлять анонимный отчёт о станции на `stats.x-servers.ru`. Функция
необязательная: пока владелец не ответил «да», станция не отправляет ничего.

## Как даётся согласие

| Где | Когда появляется |
| :-- | :-- |
| Веб-панель | окно при первом открытии, если ответа ещё нет |
| Настройки панели | тумблер «Отправлять анонимную статистику» после любого ответа |
| Установщик | вопрос после установки, флаги `--telemetry`, `--no-telemetry` |

Ответ хранится рядом с `settings.toml`, в файле `<data-dir>/telemetry.toml`:

```toml
enabled = true
consent = "granted"   # unset, granted или declined
install_id = "0f0c2b0a-4a1c-4a4b-9f0e-6a3f0f3f12ab"
```

`consent = "unset"` означает, что вопроса ещё не было: панель покажет окно, а
установщик не записал ответ. Если удалить файл, вопрос появится снова, а
`install_id` будет новым. Значение `declined` запоминается, поэтому отказавшуюся
станцию панель больше не спрашивает — остаётся только тумблер.

## Что и когда уходит

Отчёт `POST https://stats.x-servers.ru/v1/luna/events` с телом в JSON:

- через 60 секунд после старта Luna (`event = "startup"`);
- раз в час во время работы (`event = "heartbeat"`);
- сразу после включения тумблера (`event = "consent"`);
- при `--telemetry` в установщике (`event = "install"`).

Ошибка отправки не влияет на работу станции: в лог попадает предупреждение, и
следующая попытка будет через час.

### Состав отчёта

| Поле | Пример | Смысл |
| :-- | :-- | :-- |
| `schema` | `1` | версия формата |
| `event` | `heartbeat` | причина отправки |
| `install_id` | `0f0c2b0a-…` | случайный UUID установки |
| `version` | `0.2.30` | версия Luna |
| `sent_at` | `1795000000` | время отправки, unix seconds |
| `device.model` | `yandexmini3` | модель станции |
| `device.architecture` | `aarch64` | архитектура |
| `device.features` | `["input.evdev", …]` | обнаруженные возможности |
| `device.led` | `{"ring_count":6,"has_logo":true,"logo_count":1}` | топология LED |
| `device.room_set` | `true` | задана ли метка комнаты (без текста) |
| `settings` | `{…}` | включённые разрешения и флаги |
| `packages` | `[{"id":"…","version":"…","enabled":true,…}]` | установленные модули |
| `counts` | `{…}` | число модулей, runtime-токенов, вкладок, датчиков |
| `health` | `{"warnings":0,"errors":0}` | счётчики логов за запуск |
| `system` | `{…}` | ядро, память, load average, температура CPU, uptime |

В `settings` попадают только флаги и количества: `lua.permissions` целиком,
`lua.share_dir`, `updates.interval_minutes`, `web.network.allow_count` и
`lua.network_allow_count` вместо самих списков хостов.

## Чего в отчёте нет

- IP-адреса, имени сети, MAC и серийного номера;
- имени хоста и текста метки комнаты;
- файлов, содержимого пакетов, их настроек и логов;
- списка разрешённых хостов `network_allow` и `web.network.allow`;
- аккаунтов, голосовых записей и истории команд.

IP-адрес отправителя виден принимающему серверу так же, как любому HTTP-серверу;
Luna его не передаёт в теле отчёта.

## Служебные команды

```sh
luna --data-dir /data/quazar/luna/data telemetry on     # согласие и первый отчёт
luna --data-dir /data/quazar/luna/data telemetry off    # отказ, отправка прекращается
luna --data-dir /data/quazar/luna/data telemetry show   # текущее состояние
```

Свой коллектор подключается переменной `LUNA_TELEMETRY_ENDPOINT`, например
`http://127.0.0.1:8790/v1/luna/events` во время разработки.
