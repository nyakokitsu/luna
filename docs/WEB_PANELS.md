# Сторонние веб-панели

> Своя вкладка должна выглядеть и вести себя как часть Luna: общий CSS, без
> собственного дизайна, доступ к станции только через `/api`.

Luna принимает веб-панели от других модов и плагинов: страницу регистрирует
`register.customweb()`, и она открывается отдельной вкладкой в Luna Web UI.
Чтобы панели одного устройства выглядели и вели себя одинаково, к ним
предъявляются требования по оформлению и доступу.

## Требования к странице

1. **Подключайте общий CSS Luna.** В `<head>` страницы должен быть только
   базовый стиль Luna:

   ```html
   <link rel="stylesheet" href="/luna-panel.css">
   ```

   Файл отдаёт сама Luna по `GET /luna-panel.css`. Он содержит токены темы
   (светлая и тёмная), типографику и компоненты панели: `.card`, `.btn`,
   `.in`, `.fld`, `.sw`, `.pill`, `.chip`, `.kv`, `.log`, `pre`, `table`.

2. **Без собственного дизайна.** Самодеятельность в плане оформления
   нежелательна: не приносите свои шрифты, палитры, темы, тени, анимации
   загрузки и «фирменные» стили. Не переопределяйте переменные `--bg`,
   `--surf`, `--line`, `--text`, `--acc` и остальные токены `:root`, не
   подключайте сторонние CSS-фреймворки и не задавайте стили элементам
   напрямую через `style="..."`, если для этого есть класс панели.

3. **Своя разметка — только внутри карточек.** Страница не рисует сайдбар,
   навигацию, шапку и переключатель темы: это делает оболочка Luna, а панель
   открывается во фрейме. Начинайте с контейнера и заголовка:

   ```html
   <!doctype html>
   <html lang="ru">
   <head>
     <meta charset="utf-8">
     <meta name="viewport" content="width=device-width,initial-scale=1">
     <title>Мой мод</title>
     <link rel="stylesheet" href="/luna-panel.css">
   </head>
   <body>
     <div class="wrap">
       <div class="head">
         <h1>Мой мод</h1>
         <p class="mut">Управление станцией из сторонней панели.</p>
       </div>
       <div class="card">
         <h3>Состояние</h3>
         <div class="row"><span class="pill ok">На связи</span><button class="btn pri">Обновить</button></div>
       </div>
     </div>
   </body>
   </html>
   ```

4. **Тема.** `luna-panel.css` сам включает тёмную тему по
   `prefers-color-scheme`, а тему, выбранную в Luna, оболочка передаёт
   странице сама (`data-theme` на `<html>`). Дополнительный код не нужен.

5. **Только HTML из каталога пакета.** Разрешены `.html`/`.htm` до 4 МБ
   внутри каталога плагина; остальные файлы наружу не публикуются. Поэтому
   картинки и данные держите в самом HTML (data-URI или инлайн SVG), а не
   отдельными файлами.

6. **Доступ к станции — через `fetch('/api/...')`.** Подробности в
   [API.md](API.md) и в разделе «Изоляция страницы» ниже.

## Изоляция страницы

Страница открывается во фрейме с `sandbox` и отдаётся с
`Content-Security-Policy: sandbox …`, поэтому у неё собственный, непрозрачный
origin: она не видит cookies, `localStorage` и DOM Luna и не может обратиться
к API напрямую. Это не даёт странице одного пакета управлять станцией в обход
прав пакета.

Luna вставляет в начало `<head>` страницы небольшой скрипт-мост. Он
перехватывает `fetch` с относительным путём `/api/...` (или полным адресом
этой же станции) и передаёт запрос оболочке Luna, а та выполняет его с
заголовком `X-Luna-Panel: <id пакета страницы>`. Для страницы всё выглядит как
обычный `fetch`, ответ — обычный `Response`.

Через мост доступны:

- чтение `GET /api/device`, `/api/plugins`, `/api/custom-web`, `/api/media`;
- свой пакет и пакеты того же YAM-пространства имён (`airplay.panel` →
  `airplay.*`): `POST …/invoke`, `…/stop`, `…/service/start|enable|disable`,
  `GET …/logs`;
- `POST /api/http` (по-прежнему только при разрешении `web.network`);
- эндпоинты по правам пакета страницы: `led` → `/api/led…` и
  `/api/led-panel…`, `volume` → `/api/volume…`, `audio` → `/api/audio…`,
  `clock` → `/api/clock…`, `bluetooth` → `/api/bluetooth…`, `sensors` →
  `/api/sensors`, `microphone` → `/api/microphone…`, `input` → `/api/input…`.

Остальное (установка и удаление пакетов, настройки, пользовательский Lua,
owner API, Алиса) отвечает `403`. Нужен вызов — добавьте право в
`plugin.toml` или вызывайте его из своего пакета, а не со страницы.

Ограничения моста:

- тело запроса — строка, `URLSearchParams`, `ArrayBuffer`, typed array или
  `Blob`; `FormData` не поддерживается;
- `XMLHttpRequest`, `EventSource` и WebSocket к API не работают — только `fetch`;
- вне Luna (если открыть `/web/<id>` отдельной вкладкой) мост не включается и
  API недоступен;
- высоту фрейма Luna берёт по корневому `.wrap` страницы.

## Область вкладки и прокрутка

Оболочка растягивает область сторонней панели на доступную ширину вкладки.
Рамки вокруг документа нет; для страниц с корневым `.wrap` высота следует
за содержимым, включая сворачивание секций. Используется общая прокрутка
страницы Luna, а не вторая прокрутка внутри панели.

`register.customweb()` и отдельный документ панели сохраняются. Мост сообщает
оболочке высоту корневого `.wrap`, оболочка передаёт выбранную тему; к DOM
родителя у панели доступа нет.

## Внешние HTTP-запросы

Браузер клиента может не иметь доступа в интернет, а станция — иметь.
Поэтому панель не ходит во внешнюю сеть напрямую, а просит Luna отправить
запрос через `POST /api/http`:

```js
const response = await fetch('/api/http', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    method: 'GET',
    url: 'https://api.example.org/status',
    headers: { Accept: 'application/json' },
  }),
});
const { status, body } = await response.json();
```

Разрешение выдаёт владелец станции в настройках (`web.network.enabled` и
список хостов `web.network.allow`). Без него endpoint отвечает `400`, и панель
должна показать понятное сообщение, а не пустой экран. `http://` разрешается
только при `web.network.allow_insecure_http = true`; локальные адреса
запрещены всегда.

## Чек-лист перед публикацией

- страница подключает `/luna-panel.css` и не содержит собственного CSS;
- нет своих шрифтов, цветов, сайдбара и переключателя темы;
- используется `fetch('/api/...')` с относительным путём, без `FormData` и XHR;
- нужные эндпоинты покрыты правами пакета (см. «Изоляция страницы»);
- внешние запросы идут только через `/api/http`;
- панель корректно работает при выключенном разрешении и на станции без
  нужной capability.
