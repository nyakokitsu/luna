# Нативная громкость Mini 2 на прошивке .46

Проверенная конфигурация (3 ноября 2026):

- модель Luna `yandexmini_2`, плата DT `yandex,station-mini2`;
- полный номер прошивки `0.369.1.46.4793643989.20261020.299`;
- исходники Luna 0.2.18 с этим исправлением;
- официальный AirPlay `ryysel/Station-airplay` 2.0.4, без изменений его кода.

## Причина и исправление

Этой сборки не было в списке проверенных для `quasar_volume`. Luna переходила
на ALSA: API показывал 20%, а логическая громкость Quasar оставалась 15%.
AirPlay выбирал `ALSA Master (Luna volume manager unavailable)`.

Добавлен только этот полный номер прошивки с обязательным отдельным
NUL-разделённым элементом DT `yandex,station-mini2`. Похожие имена платы и
неизвестные номера сборок не допускаются. Прежние правила допуска сохранены.

Используется существующий протокол: чтение состояния `stereo_pair`,
`VolumeSet` через `iohub_clients`, подтверждение фактического уровня и
`Source=Button` для штатной индикации. Формат пакетов и HTTP API не менялись;
station-volume для работы Luna не требуется.

## Фактическая проверка

Прошли `cargo test --workspace --locked`: 83 теста, без ошибок и пропусков.
Собран статический Linux AArch64 musl binary для Mini 2, Rust 1.99.1.
Добавлены тесты точной пары build/DT, отказа похожим и неизвестным вариантам
и сохранения прежних квалификаций. Существующие проверки protobuf и шага 5%
тоже прошли.

После исправления проверены `POST /api/volume/set` и независимое чтение
логического уровня Quasar:

| Запрошено | Ответ Luna | Quasar |
|---|---|---|
| 20% | 20% | 20% |
| 25% | 25% | 25% |
| 23% | 25% | 25% |
| 0% | 0% | 0% |

Затем восстановлен исходный для этой проверки уровень 25%.

Неизменённый AirPlay 2.0.4 выбрал `Luna /api/volume`. Владелец проверил
изменение ползунка Mac и команду «Алиса, громкость три» и подтвердил
синхронизацию в обе стороны и появление индикации на колонке.
В снимках одновременно совпали Mac / AirPlay / Luna / Quasar: 30/30/30/30%
и 60/60/60/60%. Во время движения ползунка и при округлении к аппаратному
шагу 5% мгновенные показания могут различаться.

При первичной пробе Luna и плагин запускались в отдельном каталоге с ограниченным локальным API
и отключёнными обновлениями. Для проверки не перезапускались Quasar и сама
колонка, не менялись root/OTA и действующий init. Исходная рабочая версия
AirPlay и откат сохранены.

## Дополнительная проверка постоянного запуска

Затем тот же бинарник Luna установлен через YAM 0.2.5 как локальный пакет
`yam/luna 0.2.18+mini2.046.2`, вместе с официальным `airplay/airplay-luna 2.0.4`.
После одной контролируемой перезагрузки автоматически поднялись одна Luna
и один AirPlay-приёмник; плагин сохранил enabled/service_enabled, выбрал
`Luna /api/volume`. Штатный уровень 5% сохранился, Luna и Quasar показали 5/5.
`yam doctor` не обнаружил ошибок, защищённые SSH/Quasar/OTA-файлы не менялись.

Этот результат относится к локально настроенному init: он передаёт
`--yam-root`/`--yam-run`, создаёт runtime lock и ждёт готовности нативного IPC
Quasar перед запуском Luna. Код этой настройки установки не входит в PR;
штатный upstream postinstall этой проверкой не квалифицирован.

Максимальная громкость при воспроизведении, длительный soak, другие прошивки
и модели этой приёмкой не подтверждаются. Голосовые
пауза/продолжение/стоп владелец отдельно проверил на исходной Luna 0.2.18;
этот патч меняет только квалификацию нативной громкости.
