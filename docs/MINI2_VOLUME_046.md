# Mini 2: нативная громкость на прошивке .46

> Luna снова управляет логической громкостью Quasar на прошивке
> `0.369.1.46.…299`, а не пишет в ALSA напрямую.

## Проверенная конфигурация

| Параметр | Значение |
| :-- | :-- |
| Модель Luna | `yandexmini_2` |
| Device tree | `yandex,station-mini2` |
| Полный номер прошивки | `0.369.1.46.4793643989.20261020.299` |
| Исходники Luna | 0.2.18 с этим исправлением |
| AirPlay | официальный `ryysel/Station-airplay` 2.0.4 без правок кода |

Проверка выполнена 3 ноября 2026.

## Причина

Этой сборки не было в списке проверенных для `quasar_volume`, поэтому Luna
переходила на ALSA: API показывал 20%, логическая громкость Quasar оставалась
15%, а AirPlay выбирал `ALSA Master (Luna volume manager unavailable)`.

## Исправление

Добавлен ровно один полный номер прошивки вместе с обязательным отдельным
NUL-разделённым элементом device tree `yandex,station-mini2`. Похожие имена
платы и неизвестные номера сборок не допускаются; прежние правила допуска
сохранены.

Протокол не менялся: чтение состояния `stereo_pair`, `VolumeSet` через
`iohub_clients`, подтверждение фактического уровня и `Source=Button` для штатной
индикации. Формат пакетов и HTTP API те же, отдельный station-volume для работы
Luna не нужен.

## Проверка

`cargo test --workspace --locked`: 83 теста, без ошибок и пропусков. Собран
статический Linux AArch64 musl-бинарь для Mini 2 (Rust 1.99.1). Добавлены тесты
точной пары build/DT, отказа похожим и неизвестным вариантам и сохранения прежних
квалификаций; существующие проверки protobuf и шага 5% тоже прошли.

Затем проверены `POST /api/volume/set` и независимое чтение логического уровня
Quasar:

| Запрошено | Ответ Luna | Quasar |
| :-- | :-- | :-- |
| 20 % | 20 % | 20 % |
| 25 % | 25 % | 25 % |
| 23 % | 25 % | 25 % |
| 0 % | 0 % | 0 % |

После проверки восстановлен исходный уровень 25%. Неизменённый AirPlay 2.0.4
выбрал `Luna /api/volume`: владелец проверил ползунок в macOS и команду
«Алиса, громкость три», синхронизацию в обе стороны и индикацию на колонке. В
снимках одновременно совпали Mac / AirPlay / Luna / Quasar: 30/30/30/30 % и
60/60/60/60 %. Пока ползунок движется и при округлении к аппаратному шагу 5 %,
мгновенные значения могут расходиться.

Первичная проба шла в отдельном каталоге с ограниченным локальным API и
отключёнными обновлениями: Quasar и колонка не перезапускались, root/OTA и
рабочий init не менялись, исходная версия AirPlay и откат сохранены.

## Постоянный запуск

Тот же бинарь установлен через YAM 0.2.5 как локальный пакет
`yam/luna 0.2.18+mini2.046.2` вместе с официальным
`airplay/airplay-luna 2.0.4`. После одной контролируемой перезагрузки
автоматически поднялись одна Luna и один AirPlay-приёмник. Плагин сохранил
enabled/service_enabled и выбрал `Luna /api/volume`; штатные 5% сохранились,
Luna и Quasar показали 5/5. `yam doctor` ошибок не нашёл, защищённые файлы
SSH/Quasar/OTA не менялись.

Результат относится к локально настроенному init: он передаёт
`--yam-root`/`--yam-run`, создаёт runtime lock и ждёт готовности нативного IPC
Quasar перед запуском Luna. Код этой настройки в PR не входит, штатный upstream
postinstall этой проверкой не квалифицирован.

## Что не подтверждено

Максимальная громкость при воспроизведении, длительный soak, другие прошивки и
модели этой приёмкой не подтверждаются. Голосовые пауза/продолжение/стоп
владелец проверял отдельно на исходной Luna 0.2.18: патч меняет только
квалификацию нативной громкости.
