# Комнаты устройств в Luna

Комната — необязательная метка пользователя, например `Кухня`. Это не модель,
capability, разрешение, имя пакета, облачная комната Яндекса или группа multiroom.
Ядро YAM v2 не знает о Web UI, Lua и Quasar; всеми поверхностями этой функции
владеет host-пакет **`yam/luna`**.

## Хранение и валидация

- Файл `room.toml` находится непосредственно в `--data-dir` runtime, а не в
  его каталоге установки/плагинов, не в platform YAML и не в package SQLite.
- Сервисный пример `yam.yaml` передаёт `${YAM_VAR}`; используйте фактический
  runtime data-dir, не жёсткий путь старого `/data/quazar/yam`.
- Без файла комнаты нет. Непустое значение: до 64 Unicode scalar values,
  без управляющих символов; проверяется исходная строка, затем убираются пробелы
  по краям. Пустая строка, пробелы и `null` убирают метку. Это не счётчик UTF-8
  байтов и не grapheme clusters.
- Неизвестные поля и неправильные типы отклоняются. Повреждённый TOML вызывает
  явную ошибку при чтении/запуске, не маскируется отсутствием комнаты.
- Запись: отдельный create_new sibling temp, sync файла, rename и sync каталога
  на Unix. Параллельные CLI/HTTP-записи не делят temp-файл; выигрывает последняя
  успешная замена. Это не распределённая синхронизация/compare-and-swap.
- Метка не меняет `device.toml`, модель, features, permissions, ALSA, LED,
  package manifests, resolver или service state. Версии/теги не изменяются.

## CLI без запуска runtime

```sh
luna --data-dir "$RUNTIME_DATA_DIR" room
luna --data-dir "$RUNTIME_DATA_DIR" room "Кухня"
luna --data-dir "$RUNTIME_DATA_DIR" room --clear
```

Вывод — метка и перевод строки; отсутствие комнаты — пустая строка.
`room` только читает и не создаёт отсутствующий data-dir. Изменяющие команды
создают каталог при необходимости, но не инициализируют настройки, плагины,
сеть или аппаратные адаптеры и не запускают службы.

CLI — локальная команда на хосте runtime (например, в SSH), не удалённая
команда старого desktop-клиента `yam`. У ядра v2 собственные `--platform/--root`
и пакетные операции: они не используются для изменения комнаты.

## Web UI и HTTP

В панели runtime есть отдельное поле комнаты. Пустое поле удаляет метку;
сохранение не вызывает hardware-settings endpoint.

```http
GET /api/room
```

Ответ: `{"room":null}` или `{"room":"Кухня"}`.

```http
PUT /api/room
Content-Type: application/json

{"room":"Кухня"}
```

Ответ — нормализованное значение в той же форме. Некорректное значение не
перезаписывает прежний файл. `GET /api/device` добавляет необязательное поле
`room`, сохраняя прежние поля аппаратного профиля. Клиенты должны принимать
и `null`, и отсутствие поля у старых версий runtime.

Endpoint комнаты наследует существующую модель доступа управляющего API;
отдельная аутентификация этим изменением не добавляется. Не открывайте его
в недоверенную сеть/WAN; используйте loopback/SSH-туннель, если нет сетевой
изоляции. Метка комнаты может содержать личную информацию.

## Бинарные и Lua-плагины

Бинарный плагин читает `${YAM_API_URL}/device` с заголовком
`X-YAM-Token: ${YAM_API_TOKEN}`. Действующие проверки token и разрешения `exec`
не ослабляются. Нового runtime endpoint для изменения комнаты плагином нет.
Это metadata API **плагинов данного host runtime**, не API всех `.yampkg`.

Lua получает `device.room` как строку или `nil` на момент запуска. Поле не
участвует в проверке аппаратной совместимости. HTTP читает актуальный файл,
поэтому изменения CLI видны уже работающему демону. Lua/бинарный плагин,
который запоминает имя при старте, обновит его только после собственного
обычного перезапуска; смена комнаты не перезапускает его автоматически.

## Переход с v1 и откат

Старый PR #14 предназначался для встроенного `yamd`, CLI `yam` и старых путей.
В v2 они не возвращаются в ядро. Сохранён формат room.toml, но **автоматической
миграции установленного v1 нет**. При будущем согласованном переходе можно
прочитать старую метку и явно задать её CLI нового host runtime. Не запускайте
оба runtime на одном порту или на общем каталоге данных без отдельного плана.

Откат к предыдущей сборке этого runtime оставляет room.toml как неиспользуемый
файл; пакетный менеджер/профиль устройства не менялись. Это не откат v2→v1
всей установленной системы. Не обновляйте рабочую колонку ради проверки метки.

## Host-only проверки

```sh
cargo fmt --check
cargo check --locked
cargo test --locked
cargo build --locked
python3 tests/test_room_api.py target/debug/luna
```

Python-фикстура слушает только `127.0.0.1`, выключает обновления, использует
искусственный hardware profile и несуществующий LED root. Проверяет CLI,
HTTP/UI-разметку, runtime-token, неизменность hardware override, Unicode,
параллельную запись, перезапуск/сохранение и повреждённый TOML. Это не живая
браузерная/аппаратная приёмка и не квалификация всего runtime или YAM v2.
